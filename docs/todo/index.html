    Documentation Revamp TODO (Phase 2)¶

    As the project has grown, the documentation has become slightly repetitive across multiple files. The next phase of documentation should focus on creating a clear, linear structure without repeating concepts.

    Plan (2026-10-26)¶

    Work through the steps in order: fix what's broken first, document once behavior is stable, add features last. Each step points to the notes further down in this file.

    Context for a new session - Engine: engine/lua-loader.js registers the Lua globals and the metro table; engine/grid-api.js holds the grid, MIDI, synth and metro timing. index.html holds the UI (script dropdown, MIDI monitor, FX). - iii reference: the firmware repo at ../neotrellis-monome has the real API. neotrellis_monome_picosdk_iii/src/iii/lua/lib.lua (metro, midi helpers, pset), src/iii/vm.c (built-ins such as midi_tx, fs_*), src/device_lua.c (grid functions). Match those when adding to the emulator. - Testing without a browser: run the real engine in node with the fengari npm package. Set globalThis.window = { fengari: require('fengari') } and a localStorage stub, import grid-api.js and lua-loader.js, override api.midi_note_on/off to count notes, call loader._execute(source, name), then drive keys with api._luaEventGrid(x, y, z) on timers. Run all scripts in scripts/manifest.json after engine changes to catch regressions. Confirm sound changes in the dev server (npm start). - External scripts can be fetched with gh api repos/<owner>/<repo>/contents/<file>.lua --jq .content | base64 -d.

    Step 5 — New sound features¶

    • [x] Drum sounds (2026-10-26): engine/drums.js, seven drums ported from the Mangler (WAV.builder). General MIDI notes on one channel (36–51 = 4×4 pads), or a channel per drum; ⚄ re-rolls a drum; closed hat chokes open hat. In a new Sound tab.
    • [x] Sound tab pops out into a movable, resizable window (desktop); docked on mobile.
    • [x] Synth models (engine/synth.js): Triangle, Sine, Soft saw, Hollow square, Wide pad, Pluck, FM bell, with Drift (pitch wander) and Movement (filter sweep). Loudness matched (RMS 0.54–0.58).
    • [x] One place for sound (2026-10-26): the sound module under the grid is now volume, mute and ⚙ Sound; everything else is in the Sound tab (or its window). Engine in engine/sound.js.
    • [x] Several synths at once, each a tab with its own channel, preset (built-in or saved), model, envelope, drift, movement, filter (+ CC), level and sends to reverb, delay and chorus. The drum kit has level and sends too.
    • [x] Envelope editor: drag the points.
    • [x] Karplus–Strong strings (String, Nylon): computed per note into a buffer (a DelayNode feedback loop can't go above ~375 Hz); in tune within 0.4 cents from 82 to 1760 Hz.
    • [x] Chorus; reverb types Large room / hall and Plate / spring.
    • [x] Quality: Auto / Full / Light (light on phones: 6 voices per synth, short mono reverb, no chorus, no drift or movement).
    • [ ] Listen to all of it in the dev server: drum levels against the synths, the models and presets, both reverbs, the chorus.
    • [x] Long notes: the stuck-note guard is a setting (3 s, 10 s, 30 s, 1 min, never; 30 s to start with), and ■ next to the volume stops everything (All Sound Off + All Notes Off on all 16 channels, and the emulator's sound).

    Open compatibility issues (found 2026-10-25)¶

    Settled in Step 1; what's left for script writers is on the Hardware vs. Emulator page.

    • Firmware bug (for the firmware fork): lib.lua's slew.deinit() calls metro.free(slew.id), but slew.id is the metro, not its number, so it throws on the device and in the emulator. Fix: metro.free(slew.id.id), or store the number.
    • sluiiice calls metro.free(strumclock) with the metro; worth reporting to its author (see its note above).
